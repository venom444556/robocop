Technical Analysis

Static analysis reveals a 47-line PowerShell script employing multiple layers of obfuscation: Layer 1 - String Concatenation: Variable names are constructed from character arrays to evade signature-based detection. The IEX (Invoke-Expression) command is built as ('I'+'EX') and the download URL is split across 6 variables joined at runtime. Layer 2 - Base64 Encoding: The core payload delivery logic is wrapped in a Base64-encoded block decoded via [System.Convert]::FromBase64String(). The decoded content performs the actual HTTP request using System.Net.WebClient. Layer 3 - XOR Decryption: The downloaded second-stage payload is XOR-encrypted with a 16-byte key embedded in the script (0x4D,0x41,0x4C,0x57,...). This prevents network-level inspection of the payload content. Network behavior analysis indicates the following sequence: - DNS query for updates.microsoftsecurity-cdn[.]com resolving to 185.220.101[.]42 - HTTPS GET /api/v2/update?id={MACHINE_GUID} to download encrypted payload - HTTPS POST /api/v2/checkin with Base64-encoded system info The scheduled task uses schtasks.exe with the /create /tn "WindowsSecurityUpdate" /tr parameters, executing the original script from %APPDATA%\Microsoft\Windows\update.ps1. The registry persistence writes to HKCU\Software\Microsoft\Windows\CurrentVersion\Run with the value name "SecurityHealthService".
